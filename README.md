# claude-sessions

GNOME (Ubuntu) top bar indicator showing the state of every Claude Code
session open in your terminals, with a desktop notification whenever one of
them asks you something or needs permission.

```
bar:   [Claude]  ⟳  ⏸  ?  ✓        (Claude glyph + one icon per session, in start order)
Claude icon menu:
        ⟳  [Block editor refactor] Edit glossary.spec.ts
        ⏸  [ams-admin] no activity
        ?  [e2e pipeline failures] permission: $ bundle exec rspec
        ✓  [Ticket ATE-8035 screens] Still waiting for job 4583238.
        ──────────────
        Clean up dead sessions
        Quit
session icon menu:
        ?  [e2e pipeline failures] permission: $ bundle exec rspec
        /home/me/projects/ate-e2e-tests
```

The bar shows the Claude glyph first, then one state icon per session,
ordered by start time (oldest first, stable across state changes). No text.
The Claude icon opens the global menu listing every session; each session
icon opens its name, summary and working directory. Clicking a session copies
its directory to the clipboard (Wayland does not allow focusing a terminal
from outside).

| Icon (system theme)            | State   | Meaning                                                   |
|--------------------------------|---------|-----------------------------------------------------------|
| dialog-question-symbolic       | waiting | asking for permission, asking a question, plan to approve, API error |
| emblem-synchronizing-symbolic  | running | running a tool or processing your prompt                  |
| emblem-ok-symbolic             | done    | finished, waiting for your next message                   |
| media-playback-pause-symbolic  | idle    | freshly started session, no activity yet                  |

Icon names live in the `STATE_ICON` dictionary at the top of the executable.

Bar ordering: the `ubuntu-appindicators` extension inserts every new icon at
the left, ignores the ordering index, and only drops an item when its process
dies. So the indicator creates a fixed number of "slots" at startup (1 for
Claude + 12 for sessions, `CLAUDE_SESSIONS_SLOTS` environment variable) in
reverse order and assigns the sorted sessions to them, hiding the unused
ones. With more sessions than slots, the extra ones only appear in the Claude
icon menu.

The Claude glyph is rendered at startup into
`~/.local/state/claude-sessions/icons/` with cairo + librsvg. It comes from
Font Awesome Free 7 (`brands/claude`, licensed
[CC BY 4.0](https://fontawesome.com/license/free)).

## How it works

1. `install.sh` registers global hooks in `~/.claude/settings.json` that run
   `claude-sessions hook` on every relevant event. The hook reads the JSON
   from stdin and atomically writes
   `~/.local/state/claude-sessions/<session_id>.json` with state, summary,
   cwd, name, PID, start time and timestamp. It takes ~30 ms, never writes to
   stdout and always exits 0.
2. `claude-sessions indicator` (launched by autostart) watches that directory
   with `Gio.FileMonitor` plus a 5 s poll, shows one icon per session and
   runs `notify-send` the first time a session enters `waiting`.
3. If a session's PID no longer exists (terminal closed without a
   `SessionEnd`), the indicator deletes its file.
4. Live sessions without a state file yet (fresh install, or the state
   directory was wiped) are listed from Claude Code's internal registry in
   `~/.claude/sessions/` as running or idle until their first hook event.

Event mapping:

| Claude Code event                                     | State              |
|-------------------------------------------------------|--------------------|
| `SessionStart`                                        | idle               |
| `UserPromptSubmit`, `PreToolUse`, `PostToolUse`       | running            |
| `PreToolUse` for `AskUserQuestion` / `ExitPlanMode`   | waiting            |
| `PermissionRequest`, `Elicitation`                    | waiting            |
| `Notification` (except `idle_prompt`, `auth_*`, `*_complete`) | waiting    |
| `Stop`                                                | done               |
| `StopFailure`                                         | waiting (error)    |
| `SessionEnd`                                          | file deleted       |

Summary (50 chars): while running, the tool in use (Bash description, file
name, MCP tool) or the start of your last prompt; while waiting, the
permission, question or notification text; when done, the first line of
Claude's last message (for example "Still waiting for job 4583238."); idle,
"no activity". No LLM is called.

Session name: the same title the terminal shows. In priority order: the
title set with `/rename`, the title generated by Claude Code (read from the
`custom-title` / `ai-title` lines of the session transcript, an internal
format that may change between versions), and otherwise the cwd basename
plus `@branch` (except main/master). Truncated to 40 characters. Two sessions
with the same name get `·1`, `·2` suffixes. The title is read from the tail
of the transcript by the indicator, not by the hook, cached by mtime/size.

## Install

### From the .deb (recommended)

Download `claude-sessions_<version>_all.deb` from the GitHub release and:

```bash
sudo apt install ./claude-sessions_<version>_all.deb
```

This installs `/usr/bin/claude-sessions`, a system-wide autostart entry in
`/etc/xdg/autostart/` and an application launcher, and pulls the apt
dependencies. The hooks are per user, so they are registered in
`~/.claude/settings.json` (with a backup) the first time the indicator starts
in your session, or right away with:

```bash
claude-sessions setup        # register hooks for the current user
claude-sessions indicator &  # start it now; it autostarts at the next login
```

Sessions that are already open show up right away: the indicator seeds them
from Claude Code's own session registry (`~/.claude/sessions/`) until their
first hook event arrives.

To remove it: `claude-sessions unsetup` (drops the hooks from your
settings.json), then `sudo apt remove claude-sessions`.

Build the package locally with `./make-deb.sh [version]`; the output lands in
`dist/`. Only `dpkg-deb` is needed.

### From the repo (development)

```bash
./install.sh
```

Installs any missing apt packages (`python3-gi`, `python3-gi-cairo`,
`gir1.2-gtk-3.0`, `gir1.2-ayatanaappindicator3-0.1`, `gir1.2-rsvg-2.0`,
`libnotify-bin`), symlinks `~/.local/bin/claude-sessions` to the executable
in this repo, backs up `~/.claude/settings.json` and adds the hooks without
touching existing ones, creates
`~/.config/autostart/claude-sessions-indicator.desktop` and starts the
indicator.

Sessions that were already open show up after their next event. If you move
the repo, run `install.sh` again.

Requirement: the `ubuntu-appindicators` GNOME extension (enabled by default
on Ubuntu). Check with `gnome-extensions list --enabled | grep appindicator`.

## Uninstall

```bash
./uninstall.sh
```

Removes only the hooks whose command ends in `claude-sessions hook` (via
`claude-sessions unsetup`, which backs up `settings.json` first), the
autostart entry, the symlink and the state directory. apt packages are left
installed.

## Releases

Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which builds the
`.deb` with `make-deb.sh`, runs `lintian`, installs the package on the runner
as a smoke test, and publishes it as a GitHub release asset. The executable
reports the tag version with `claude-sessions --version`.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

## Debug

```bash
claude-sessions status          # list sessions in the terminal
claude-sessions clean           # delete sessions whose PID is gone
ls ~/.local/state/claude-sessions/
cat ~/.local/state/claude-sessions/<session_id>.json
cat ~/.local/state/claude-sessions/indicator.log   # indicator output
cat ~/.local/state/claude-sessions/indicator.pid   # indicator PID (single instance)
```

Restart the indicator: `kill $(cat ~/.local/state/claude-sessions/indicator.pid); claude-sessions indicator &`
or simply run `./install.sh` again.

Simulate a hook event by hand:

```bash
echo '{"session_id":"test-1","hook_event_name":"PermissionRequest","cwd":"'$PWD'",
       "tool_name":"Bash","tool_input":{"command":"rm -rf build"}}' | claude-sessions hook
claude-sessions status
echo '{"session_id":"test-1","hook_event_name":"SessionEnd"}' | claude-sessions hook
```

Since a test `session_id` has no live `claude` process, the indicator deletes
that file on its next refresh (≤5 s). To keep it around during a test, run the
hook from inside a real Claude Code session (the hook walks up the process
tree until it finds `claude`).

To see the hooks Claude Code has loaded: `/hooks` inside a session.
Run the indicator in the foreground to see errors: `claude-sessions indicator`.

## Files

- `claude-sessions`: Python 3 executable (stdlib + the system's PyGObject).
  Subcommands `indicator` (default), `hook`, `status`, `clean`, `setup`,
  `unsetup`, `--version`.
- `install.sh`, `uninstall.sh`: development install from the repo (symlink).
- `make-deb.sh`, `packaging/`: Debian package build.
- `.github/workflows/release.yml`: builds and publishes the `.deb` on tags.
